I did not edit files, print secrets or data, run Docker, or make network calls. I read the files listed in the request, plus `src/harness.ts`, `src/settings.ts`, `src/chats.ts`, `public/login.js`, `public/review-view.js`, the relevant parts of `public/app.js`, and `NodeExecutionEnv` in `node_modules`. I did not read `src/review.ts` or `src/notice.ts` in full, or `public/index.html`. I did not run the test suite.

**Overall:** I found no exploitable high-severity issue. Password comparison is timing-safe, and the secret is read only from a file. The compose hardening is solid. The main gaps are the WebSocket Origin check, the runner's lack of authentication, session lifetime, and crash-on-rejection behaviour.

### Medium

1. **Cross-site WebSocket hijacking is possible from other localhost ports.** `src/server.ts:140-143` checks the cookie in `verifyClient` but never checks `Origin`. `SameSite` ignores the port, so any other local page on another port counts as same-site and its WebSocket carries the cookie. *Fix:* in `verifyClient`, reject unless `req.headers.origin === "http://" + config.host + ":" + config.port` (or an explicit allowlist).

2. **The runner accepts unauthenticated requests.** `runner/server.ts:151-165` has no credential check. `src/tools/remote-env.ts:43-53` sends no auth header. Anything on the `tools` network gets a full shell (`/v1/exec`). *Fix:* read a shared secret from a file in both containers, check it with `timingSafeEqual` in the runner, and send it as a bearer header from `remote-env.ts`.

3. **The runner's workspace guard fails open for dangling symlinks.** `runner/server.ts:39-47` (`insideWorkspace`) walks up to the nearest path that `realpathSync` can resolve. For a dangling symlink inside `/workspace` whose target is outside, the walk stops at the workspace, so the check passes. `writeFile` then follows the link. The bash tool can already do this, so the guard is advisory and the real boundary is the bind mount. *Fix:* use `lstat` on the final component and reject any symlink whose target resolves outside `ROOT`.

4. **The path check is skipped for non-string arguments.** `runner/server.ts:102` only checks `typeof args[0] === "string"`. The `$bytes` decoding can produce a `Uint8Array`, which skips the check. I checked `node_modules/.../dist/env/node.js:30` (`resolvePath` calls `path.startsWith`), so this currently throws and is not exploitable. *Fix:* reject any non-string path argument before the check.

5. **Sessions never expire, and logout does not revoke anything.** The cookie is `sessionValue(token)` (`src/auth.ts`, `sha256("session:"+token)`) with no `Max-Age` (`src/server.ts:82`). Logout (`src/server.ts:90`) only clears the browser's copy. A copied cookie stays valid until the token file changes and the app restarts. *Fix:* issue random session IDs stored server-side with an expiry (for example 12 h), and revoke them on logout.

6. **The session cookie has no `Secure` flag.** `src/server.ts:82` and `:90`. *Fix:* add `Secure` (browsers accept it on `http://localhost`), or set it from config when the app runs behind TLS.

7. **Unhandled rejections can crash the whole process.** `src/server.ts:246-248`: `await watch?.stop()` in the close handler is not caught. `runner/server.ts:60` and `:114`: `void closeHandle(id)` can reject if `reader.close` throws. Node 24 exits on unhandled rejections. In the runner that kills every tool call, and in the app it drops every open chat. *Fix:* wrap both in `try/catch` and add `process.on("unhandledRejection", log)`.

8. **WebSocket messages have no size limit.** `src/server.ts:140` uses the `ws` default `maxPayload` of 100 MiB. `submit.content` and `compact.instructions` are not capped, so a large message goes into SQLite and to the Anthropic API. *Fix:* set `maxPayload: 256 * 1024` and cap `content` length.

9. **The login lockout is racy and its map grows without bound.** `src/server.ts:65` reads the failure record before `await readBody`, and `:74` writes it after. Parallel requests therefore all get guesses in before the count rises. The `failures` map (`:41`) is never pruned. The key is `remoteAddress` (`:44-46`), so every client behind a proxy shares one bucket. *Fix:* reserve an attempt per key before reading the body, and prune expired entries.

10. **Chats beyond 200 disappear from the sidebar and miss settings.** `src/server.ts:121` and `:132` use `scanConversations({}, 200)`. Chats past that cap are not listed and do not get `applyToAll` settings. *Fix:* paginate both.

### Low

11. **Raw error strings reach the browser.** `src/server.ts:167` and `:242` send `String(error)`. `runner/server.ts` (`send(res, 500, …)`) returns internal messages to the app. `src/review.ts:145` puts reviewer error text into the transcript. *Fix:* log the full error with an ID server-side and send the browser a generic message plus that ID.

12. **No security headers.** `src/server.ts:93-111` sets none of CSP, `X-Frame-Options`, `X-Content-Type-Options`, or `Referrer-Policy`. Mitigation: the cookie is HttpOnly and SameSite=Strict, so a cross-site frame gets no session. *Fix:* send `content-security-policy: default-src 'self'; frame-ancestors 'none'`, `x-content-type-options: nosniff`, and `referrer-policy: no-referrer`, after checking `index.html` for inline scripts.

13. **Static serving has no allowlist.** `src/server.ts:93-106` serves any file in `public/`. The `..` check and `normalize` are adequate, but an explicit map of five files is safer. *Fix:* replace the `readFile(join(publicDir, name))` lookup with a map.

14. **An oversized login body leaves the request open.** `src/server.ts:51` throws but does not destroy the socket or send 413. *Fix:* call `req.destroy()` or respond 413 at that point.

15. **Token policy checks only length.** `src/auth.ts` (`readAccessToken`) accepts any string of at least 32 characters, so a weak but long token passes. *Fix:* require high-entropy generation (for example `openssl rand -base64 32`) and document it.

16. **The runner body reader has no size limit.** `runner/server.ts:89-93` buffers the whole request body. *Fix:* cap at 1 MiB.

17. **Method lookup uses plain object keys.** `runner/server.ts:99` (`CALLS[body.method]`) matches `constructor` and `toString`. It is harmless today. *Fix:* use `Object.hasOwn(CALLS, body.method)`.

18. **Shutdown is incomplete.** `src/server.ts:256-258` calls `server.close()` but does not close WebSocket clients, has no timeout, and a second signal re-runs `harness.close`. *Fix:* terminate `wss.clients`, race against a 5 s timeout, and guard against re-entry.

19. **Remote tool calls have no timeout.** `src/tools/remote-env.ts:43-53` (`post`) waits indefinitely if the runner hangs. *Fix:* add `signal: AbortSignal.any([context?.abortSignal, AbortSignal.timeout(30_000)])`.

20. **The app image ships devDependencies.** `Dockerfile:6` runs `npm ci` with devDependencies, and the app stage runs `tsx` from them. *Fix:* compile with `tsc` in a builder stage and install with `--omit=dev` for runtime.

21. **Settings values are coerced loosely.** In the `settings` branch of `src/server.ts`, `Number(msg.contextLimit)` accepts `[100000]` or `"100000"`. *Fix:* check `typeof === "number"` before `Number`.

22. **Logout works on GET.** `src/server.ts:90` lets any page trigger a logout. *Fix:* use POST, or accept the risk.

23. **Design note: egress plus unauthenticated shell.** With `compose.internet.yaml`, the runner has internet access and an unauthenticated shell. Injected content in a tool result could steer the agent to exfiltrate workspace files. The runner holds no credentials. *Fix:* keep egress off by default and add an allowlist proxy when it is needed.

### Tests

- `tests/auth.test.ts` covers only the cookie helpers and `tokenMatches`. Nothing tests lockout (429 after 5 failures), `POST /login`, `readAccessToken`, the WebSocket `verifyClient`, static path traversal, or the runner's `insideWorkspace`.
- `src/server.ts` and `runner/server.ts` start a listener and do top-level `await` on import, so they cannot be tested as modules. Extract `createApp(config)` and `createRunner(config)` factories so tests can drive them.
- No test covers the dangling-symlink case (finding 3) or a non-string path argument (finding 4).
- No test covers graceful shutdown or the close-handler rejection path (finding 7).

### Positives

- `src/auth.ts`: the token is compared as SHA-256 digests with `timingSafeEqual`.
- `src/config.ts`: the Anthropic key is read only from a file and is never logged. Error messages name the path, not the contents.
- `compose.yaml`: non-root users, `read_only`, `cap_drop: ALL`, `no-new-privileges`, the runner on an internal network, and the app published on `127.0.0.1` only.
- `.dockerignore` excludes `secrets/` and `data/`, and the Dockerfile copies only `src`, `public`, and `runner`.
